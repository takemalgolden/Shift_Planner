# 共有フォルダー版 シフトプランナー 2.2 利用ガイド

このアプリは、担当者が希望休を提出し、管理者がシフトを作成・確認するためのWindows用アプリです。

データの受け渡しには、会社のネットワーク内にある「共有フォルダー」を使います。管理者のアプリを常に開いておく必要はありません。ただし、共有フォルダーへつながる社内ネットワークは必要です。


## 2.2で追加：勤務時間帯・勤務の並び順の希望

担当者の「希望休提出」画面上部に「勤務時間帯・並び順の希望」を追加しました。従来の希望休とは別に、次の条件を1件ずつ提出できます。

- 日付ごとの早番・中番・遅番・ショートの希望
- 日付ごとの「この時刻以降に開始」「この時刻までに終了」という範囲の希望
- 対象月の「前日が早番なら翌日は遅番を希望」などの並び順

「翌日」は次の暦日です。休みを飛ばした次の出勤日ではありません。並び順の希望は両日とも勤務がある場合に評価し、休みの日を出勤日に変える条件にはなりません。前月末の確定済み勤務も参照します。日付別の勤務帯・時間範囲を希望した日が休日になった場合は「勤務なし」として未達一覧に表示します。

### 担当者の操作

1. 「希望休提出」で対象月を選びます。
2. 「勤務時間帯・並び順の希望」で種類・日付・勤務帯や時間を指定します。
3. 必要に応じて備考を入力し、「勤務希望を提出」を押します。
4. 管理者の取り込み後、同じ画面の一覧で申請中・承認・却下を確認します。

初回設定済みのPCなら、共有接続が切れていても提出内容をPCに保存し、接続後に送信します。提出待ちの間は「登録・取り込み済み」の一覧にはまだ出ないため、画面上部の提出状態を確認してください。入力フォームは送信前の自動保存には対応していません。提出操作をしてから画面を閉じてください。

新しい勤務希望の提出はこの画面から行います。別ウィンドウの下書き入力・従来のJSONファイルは、これまでどおり希望休・連絡事項用です。審査前の取り込み済み勤務希望は「編集して再提出」で変更できます。取り消したい場合や審査済みの変更は管理者へ連絡してください。

### 管理者の操作

1. 上部の「提出を取り込む」を押します。
2. 「希望休・承認」を開き、対象月を選びます。
3. 勤務希望の一覧で「確認・変更」を押し、内容を確認して「承認して生成に反映」または「却下・生成の対象外」で保存します。
4. 備考から条件を登録する場合は「元の備考を選択」を使います。原文と担当者が入力欄にコピーされるので、希望の種類・日付・勤務帯・時刻を管理者が指定して保存します。備考の選択だけでは条件は登録されません。
5. 「シフト管理」でシフトを生成します。
6. 画面下部の「満たせなかった勤務希望」で、対象者・対象日・希望・実際の割り当て・備考を確認します。手動修正後も現在のシフトと比較して表示します。

文章だけを自動で解釈して勤務を割り当てることはありません。選択できる備考は、対象月の希望休備考と画面で読み込んだ日付なし連絡事項です。例えば「18時まで」という備考なら、管理者が「開始・終了時刻の範囲」を選び、終了の上限を18:00として登録してください。複数の条件がある場合は分けて登録できます。対応していない複雑な条件は、備考を確認して手動で調整してください。

**生成に使うのは承認済みの条件だけです。** 必要人数、保有スキル、勤務日数、承認済み休暇などとの兼ね合いで、希望を満たせないことがあります。希望同士が矛盾する場合も未達一覧で確認できます。最適な組み合わせや全希望の達成を保証するものではありません。

条件を保存しても、作成済みのシフトが自動で書き換わることはありません。必要に応じて再生成してください。再生成ではその月のシフトが作り直されるので、手動修正済みの内容に注意してください。確定済みの月は先に「再編集する」を押します。一次確認済みの月で条件を変更すると下書き状態へ戻ります。

### 2.1から2.2へ更新する場合

1. 全員の送信待ちを送信し、管理者が取り込んだうえでバックアップを保存します。共有フォルダー全体もバックアップしてください。
2. 全員のアプリを終了します。
3. 管理者は2.2の配布一式を別フォルダーに展開して起動し、従来と同じ共有フォルダーを使います。初期化コマンドを再実行しないでください。
4. 管理者が新しい担当者配布ZIPを作成し、全担当者のアプリを2.2へ更新します。
5. 旧版と新版の混在を避け、旧版は起動しないでください。既存の社員番号・パスワード・業務データを保持したまま、勤務希望を保存する項目が追加されます。

## 1. 担当者の使い方

### 初めて使うとき

1. 管理者から「担当者用の配布ZIP」を受け取ります。
2. ZIPファイルを右クリックし、「すべて展開」を選びます。自分のPC内の分かりやすい場所へ、全ファイルを展開してください。
3. 展開したフォルダーにある `担当者用起動.bat` をダブルクリックします。「.bat」は、アプリを開くための起動ファイルです。
4. 社員番号とパスワードを入力し、ログインします。

**共有フォルダーの場所は管理者が設定済みです。担当者によるパスの入力は不要です。** 同梱の `deployment.json` は接続先の設定ファイルなので、削除・移動せず、アプリと同じフォルダーに置いてください。

まだアカウントがない場合は、管理者に案内された社員番号で「新規登録を申請」します。管理者が申請を取り込み、承認するまでログインできません。初回の利用には、共有フォルダーへの接続と、利用するWindowsアカウントの事前登録も必要です。

> 旧版を利用していた方へ：「社員番号」は、以前の「ログインID」の表示名を変えたものです。これまでのログインIDとパスワードで利用できます。会社の実際の社員番号へ自動的に置き換わるわけではありません。

### 希望休を提出する

1. 「希望休提出」を開き、対象月を選びます。
2. カレンダーで希望する日を選びます。カレンダーは日曜日から始まります。
3. 日付ごとに休暇の種類、終日・午前・午後の区分、必要な備考を入力します。
4. 提出の操作を行います。
5. 画面上部の「提出・受付結果」で、提出後の状態を確認します。

日付を指定しない連絡事項も提出できます。管理者がアプリを閉じていても、共有フォルダーへ提出できます。

### 「提出した」と「承認された」は違います

提出後は、次の順番で処理されます。

**担当者が提出 → 管理者が取り込む → 管理者が内容を審査 → 承認・却下の結果を確認**

| 表示・状態 | 意味 |
| --- | --- |
| 送信待ち・取り込み待ち | PC内で送信を待っているか、管理者の取り込みを待っています。 |
| 取り込み済み | 管理者側へ内容が届きました。休暇の承認が済んだという意味ではありません。 |
| 承認・却下 | 管理者の審査結果です。希望休の画面で、コメントとあわせて確認してください。 |

取り込み前の希望は、画面上部から取消依頼を提出できます。審査済みの希望を変更したい場合は、管理者へ相談してください。

### ネットワークにつながらないとき

そのPCで初回設定・アカウント承認・ログインを済ませていれば、PCに保存された本人用データを使ってログインし、入力や提出内容の保存ができます。

- 接続できない間の提出内容は、そのPCに保存されます。
- アプリの起動時・操作時・起動中の約60秒ごとに、共有フォルダーへの送信を試みます。
- アプリを閉じている間は送信しません。接続が戻ったらアプリを開き、提出状況を確認してください。
- 別のPCに保存した送信待ちデータは、その元のPCから送信する必要があります。

初めて使うPCでは、ネットワークにつながらない状態から利用を始めることはできません。下書き入力の場合も同じです。

### 下書きを保存する・ファイルで渡す

ログイン後、「オフライン提出」の画面から下書き入力画面を開けます。画面内の見出しは「下書き・JSON提出」です。下書き入力では、複数日の希望、日ごとの備考、日付を指定しない連絡事項を入力できます。

「JSON」は、このアプリで読み込める入力内容の保存ファイルです。中身を自分で編集する必要はありません。

1. 下書きを入力し、JSONファイルとして保存します。
2. 担当者用アプリの「下書き・JSON提出」で、そのファイルを選んで提出します。管理者にファイルを渡し、代わりに取り込んでもらうこともできます。
3. 提出後は「提出・受付結果」を確認します。

**下書きを保存しただけでは提出されません。** また、下書きの日付を選択解除しても、提出済みの希望は取り消されません。

管理者用の配布一式に含まれる `下書き入力用.bat` を使う場合も、最初にログインが必要です。

## 2. 管理者の使い方

### 毎回の基本的な流れ

1. `管理者用起動.bat` を開き、社員番号とパスワードでログインします。
2. 画面上部の「提出を取り込む」を押し、担当者から届いた提出を集めます。
3. 「希望休・承認」で、希望休や連絡事項を審査します。
4. シフトを自動生成し、必要に応じて手動で修正します。人数不足などの警告も確認してください。
5. 一次確認、二次確認・確定を行います。確定したシフトは、担当者本人の画面で確認できるようになります。
6. 作業が終わったらログアウトし、アプリを終了します。

新規登録の申請を取り込むときや、日付を指定しない連絡事項を審査するときは、先に「共通設定の編集権を取得」を押してください。

Excel、個人別のExcelをまとめたZIP、CSVの出力と、業務データのバックアップも利用できます。保存操作をすると、保存先を選ぶ画面が開きます。

### 複数の管理者で使うとき

同時に保存して内容を上書きしないよう、「今、誰が編集できるか」をアプリが管理します。これを「編集権」と呼びます。

| 作業 | 同時利用のルール |
| --- | --- |
| 同じ月のシフトを開く | 1人が編集し、ほかの管理者は閲覧できます。 |
| 別々の月を編集する | 並行して作業できます。 |
| 従業員・勤務パターン・必要人数・半休の境界時刻などを編集する | 全員に関わる共通設定のため、ほかの管理者による月や共通設定の編集も制限されます。 |

編集できない場合は、画面上部の表示を確認し、作業中の管理者と調整してください。対象月や画面の切り替え、ログアウト、アプリの終了によって編集権は切り替わるか解放されます。

ほかの管理者が編集中の月に関係する提出は、取り込みが保留されることがあります。その担当者の後続の提出も、順番を守るため保留されます。編集が終わってから、もう一度「提出を取り込む」を押してください。

画面が古いという案内が出た場合は、更新して最新の内容を確認してから保存します。共有フォルダー内のロックファイルを手動で削除しないでください。

### 担当者用アプリを配布する

この操作は、次の「初めて導入するとき」の共有フォルダー設定とWindowsアカウント登録が済んでから行います。

1. 管理者用アプリにログインします。
2. 画面上部の「担当者配布ZIPを作成」を押します。
3. 保存先を選び、作成されたZIPを担当者へ渡します。
4. 担当者には「ZIPをすべて展開し、担当者用起動.batを開く」と案内します。

ZIPには、アプリ、共有フォルダーの接続先設定、起動ファイル、説明書が入ります。パスワード、個人データ、管理者用の秘密鍵は入りません。

配布に使う共有フォルダーの場所は、`\\fileserver\業務共有\シフト管理` のような、PC間で共通に使える形式にしてください。`C:\...` など管理者PC内だけの場所を設定している場合は、配布ZIPを作成できません。

共有フォルダーの場所を変更する場合は、社内IT担当者と調整し、変更後の設定でZIPを作り直して配布してください。

## 3. 初めて導入するとき（管理者・社内IT担当者向け）

日々の利用者が行う作業ではありません。アクセス権やWindowsアカウントの設定に不慣れな場合は、この章を社内IT担当者へ渡してください。

### 必要なもの

- Windows 10または11の64ビット版PC
- Microsoft Edge WebView2 Runtimeと.NET Framework 4.8以降（画面を表示するための部品。導入状況は社内IT担当者が確認します）
- 社内ネットワークから利用できるWindows共有フォルダー
- 担当者ごとのWindowsアカウントと、管理者をまとめたWindowsグループ

利用者PCへのPythonのインストール、専用Webサーバーの起動、ポート開放、HTTPS証明書の設定は不要です。会社のファイル共有の仕組みは稼働している必要があります。

アプリ本体は、各PC内のフォルダーに置きます。共有フォルダーには、提出内容やシフトなど、受け渡し用のデータを保存します。

### 同梱ファイルの役割

| ファイル | 用途 |
| --- | --- |
| `管理者用起動.bat` | 管理者が日常の作業を始めるときに開きます。 |
| `担当者用起動.bat` | 担当者が開きます。担当者には管理者が作成した配布ZIPを渡してください。 |
| `下書き入力用.bat` | ログイン後に下書き・JSONの画面を開きます。 |
| `CallCenterShiftShared.exe` | アプリ本体です。起動ファイルと同じ場所に置きます。 |
| `SharedFolderSetup.exe` | 社内IT担当者が、共有フォルダーの初期設定とWindowsアカウントの登録に使います。 |
| `検証結果.md` | 開発時に確認した内容と、導入先で確認が必要な項目です。 |
| `SHA256.json` | 配布ファイルの確認用情報です。通常の利用では開く必要はありません。 |

### 設定する順番

1. **管理者用のWindowsグループを用意する。** 複数の管理者がいる場合は、全員をそのグループに登録します。
2. **アプリ専用の、空の共有フォルダーを用意する。** 既存の業務ファイルが入ったフォルダーは指定しないでください。
3. **共有フォルダーを初期設定する。** 下の社内IT向けコマンドを使います。
4. **管理者用アプリを起動する。** 初回は共有フォルダーの場所を入力し、最初の管理者アカウントを登録してログインします。旧版から移行した場合は、既存のアカウントを使います。
5. **担当者のWindowsアカウントと社員番号を対応付ける。** 利用するPC・アカウントを確認し、下の登録コマンドを実行します。
6. **担当者用ZIPを作成して配布する。** 管理者画面上部の「担当者配布ZIPを作成」を使います。
7. **新規アカウントの申請を承認する。** 担当者が申請したら、管理者は「共通設定の編集権を取得」→「提出を取り込む」→「従業員管理」の順に進み、承認します。既存の承認済みアカウントは、再申請せず利用できます。
8. **実際に使うPCで試す。** ログイン、希望休提出、取り込み、承認、シフト表示と、複数管理者による同時操作を確認してから利用を始めます。

### 社内IT向け：設定コマンド

以下は、`SharedFolderSetup.exe` があるフォルダーで実行するコマンドの例です。例の共有パス、社員番号、SIDは、実際の環境の値に置き換えてください。`S-1-5-21-...` は説明用の省略表記であり、そのまま実行する値ではありません。

**SIDとは：** Windowsがアカウントやグループを区別するための識別番号です。アプリの社員番号とは別のものです。

#### 共有フォルダーの初期設定

管理者グループのメンバーとして、書き込み可能な場所から実行します。`--admin-sid` には、管理者全員が所属するWindowsグループのSIDを指定してください。

```bat
SharedFolderSetup.exe init --share "\\fileserver\業務共有\シフト管理" --admin-sid "S-1-5-21-..."
```

この操作は、空の専用フォルダーだけを対象にしてください。ツールは空でないフォルダーへの初期化を拒否します。

初期設定では、フォルダーに元から引き継がれているアクセス権を解除し、管理者グループ・設定実行者・SYSTEMに完全制御を付けます。設定するのはファイルやフォルダー自体の権限（NTFSアクセス権）です。ファイルサーバーの共有設定側の権限（SMB共有アクセス許可）は、社内IT担当者が別途確認してください。両方で必要な操作が許可されている必要があります。

#### 担当者のWindowsアカウントを登録する

担当者が実際に使用するWindowsアカウントで、次を実行してSIDを確認します。

```bat
whoami /user
```

管理者は、確認したSIDと、アプリで使用する社員番号を指定して登録します。以下の `worker01` は社員番号の例です。

```bat
SharedFolderSetup.exe enroll --share "\\fileserver\業務共有\シフト管理" --sid "S-1-5-21-..." --username "worker01"
```

- 会社で一元管理するドメインアカウントなら、PCが変わっても同じSIDを使えます。
- PCごとに別のローカルWindowsアカウントを使う場合は、各SIDを同じ社員番号に登録してください。
- 1つのWindows SIDを、複数の社員番号に割り当てることはできません。
- 新規登録予定の社員番号も、事前に割り当てできます。

Windowsへのログイン用アカウントと、共有フォルダーへの接続用アカウントが異なる環境では、`--sid` にPCへのログイン用SID、追加の `--access-sid` にファイルサーバーで認証される本人のSIDを指定します。

```bat
SharedFolderSetup.exe enroll --share "\\fileserver\業務共有\シフト管理" --sid "S-1-5-21-..." --username "worker01" --access-sid "S-1-5-21-..."
```

全員で同じ共有接続アカウントを使うと、本人ごとのアクセス制限ができません。SIDの確認や登録ができない場合は、接続先で認証されるアカウントを確認してください。

## 4. 困ったとき

| 困っていること | 確認すること |
| --- | --- |
| 起動時に配布設定がないと案内される | 管理者が作成した担当者用ZIPを、すべて展開したか確認します。`deployment.json` とアプリ本体は同じ場所に置いてください。 |
| 初回に共有フォルダーへ接続できない | 社内ネットワークへの接続、共有フォルダーの場所、Windowsアカウントの登録・アクセス権を管理者へ確認します。 |
| ログインできない | 社員番号・パスワードを確認します。新規登録の場合は、管理者の取り込みと承認が終わっているか確認します。 |
| パスワードを忘れた | 管理者へ連絡してください。管理者は従業員管理でパスワードを再設定できます。 |
| 提出したのに承認されていない | 「取り込み済み」は承認ではありません。希望休画面の審査結果を確認します。 |
| 送信待ちが残っている | 入力した元のPCでアプリを開き、ネットワーク接続と「同期・更新」を確認します。管理者の取り込み待ちの場合は管理者へ連絡します。 |
| 管理者なのに編集できない | ほかの管理者が同じ月や共通設定を編集中でないか確認します。 |
| 提出の取り込みが保留になる | 対象月を編集中の管理者の作業終了を待ち、再度取り込みます。 |
| 配布ZIPを作成できない | 管理者のログイン状態と、共有パスが `\\サーバー名\共有名` 形式であることを確認します。 |

パスワードの変更や利用停止は、ネットワークにつながっていないPCへはすぐに反映されません。次に共有フォルダーと同期したときに反映されます。

社員番号の入力条件は、従来どおり半角英数字と `.` `_` `-` の3～32文字です。カレンダー表示は日曜始まりですが、週最大勤務日数などの計算ルールは従来のままです。

## 5. 旧版からの切り替え（管理者・社内IT担当者向け）

切り替え作業は、利用者に停止時間を案内したうえで行ってください。

1. 旧アプリでバックアップを保存します。
2. 旧版に送信待ちがある場合は、旧版で受信を済ませます。難しい場合はJSONに保存し、切り替え後に管理者が取り込みます。
3. 旧サーバーと旧担当者アプリを終了します。
4. バックアップファイル（SQLite形式）を、設定作業を行うPC内に置きます。元のデータは残しておいてください。
5. 新しい空の専用共有フォルダーに、次のコマンドでデータを移します。

```bat
SharedFolderSetup.exe init --share "\\fileserver\業務共有\シフト管理" --admin-sid "S-1-5-21-..." --migrate "C:\移行用\callcenter_backup.sqlite3"
```

6. 新版へ既存の管理者アカウントでログインし、従業員、希望休、連絡事項、勤務パターン、必要人数、確定シフト、各種出力を確認します。
7. 担当者のWindowsアカウントを登録し、新しい担当者用ZIPを配布します。
8. 実際に使うPCで動作とアクセス権を確認し、新版へ切り替えます。

社員番号・パスワード・業務データは引き継ぎますが、再ログインは必要です。旧版の暗号化された送信待ちデータを、そのまま新版へ移す機能はありません。

**切り替え後は旧版を使わないでください。** 旧版と新版を並行して使うと、データが別々に保存されます。旧版へ戻す場合は新版の利用を止めます。新版で入力した変更を旧版へ自動で戻す機能はありません。

## 6. バックアップとPCの交換

管理者は、管理画面から業務データのバックアップを定期的に保存してください。あわせて社内IT担当者は、アプリ専用の共有フォルダー全体をバックアップしてください。

画面から保存する業務データだけでは、共有先の設定や、まだ取り込まれていない提出などをすべて復旧できません。復旧するときは、全員のアプリを終了し、同じ時点の共有フォルダー一式を復元します。

PC内にも下書きや送信待ちデータが保存されます。**PCの交換・初期化・アプリ関連フォルダーの削除の前に、送信待ちがないことを確認してください。** 別PCへ自動で引き継がれるわけではありません。

社内IT担当者向けのPC内保存先：

```text
%LOCALAPPDATA%\CallCenterShiftShared\admin
%LOCALAPPDATA%\CallCenterShiftShared\operator
%LOCALAPPDATA%\CallCenterShiftShared\draft
```

管理者PCの保存データには、全員分の業務データが含まれます。管理者用WindowsアカウントとPCを適切に管理してください。

## 7. 導入前に確認すること

開発時の検証はダミーデータで行っています。会社ごとにネットワークやアクセス権の設定が異なるため、本番利用の前に社内IT担当者と次を確認してください。

- 各担当者がログイン・提出でき、自分の結果を確認できること
- 担当者が、ほかの担当者の情報や管理者用データを開けないこと
- 複数の管理者が同じ月・別の月を開いたときに、編集の制限が働くこと
- ネットワーク切断後や共有サーバーの再起動後に、送信・取り込みを再開できること
- バックアップと復旧の担当者・手順が決まっていること

## 付録：保守担当者向けの情報

ここから先は、通常の利用には必要ありません。

### 共有フォルダーの主な保存内容

| 場所 | 保存するもの |
| --- | --- |
| `管理データ` | 全体の業務データ、担当者の登録情報、提出を読み取るための秘密鍵など。管理者用です。 |
| `担当者\各SID\提出` | 本人が送った、暗号化された提出ファイル。 |
| `担当者\各SID\結果` | 本人用のシフト、審査結果、受付結果。 |
| `inbox_public.pem` | 提出を暗号化するための情報。 |

これらのファイルはアプリが管理します。日常の運用で直接編集・削除する必要はありません。

共有フォルダー上のSQLiteデータを、各PCからデータベースとして直接開く方式ではありません。管理者PC内へコピーして処理し、ほかの保存と重ならないよう制御してから共有先へ保存します。担当者用データには、ほかの担当者の氏名・パスワード情報・希望休・シフトを含めません。受領記録を業務データと一緒に保存し、再送による二重登録を防ぎます。

PC内の下書きは、Windowsアカウントに対応する暗号化機能（DPAPI）で保護します。配布設定の `deployment.json` は、そのPCに以前保存した共有パス設定より優先されます。

### ソースからアプリを作り直す場合

開発・保守用PCにPython 3.12の64ビット版を用意し、ソース一式の `build_shared_windows.bat` を実行します。必要なライブラリの導入、テスト、2つのEXEの作成、配布ZIPの生成を行います。利用者PCにはPythonは不要です。

旧HTTPサーバーのソースは、既存の業務処理やテストを利用するために残しています。新版EXEではHTTPサーバーを起動しません。
